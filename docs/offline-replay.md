# 离线录像

右击主窗口左下角的头像，选择「离线播放」或「录像转码」。两个入口无需登录，分别打开独立窗口。

在「离线播放」中选择文件或拖入窗口，右侧可以切换和移除录像，并查看 TAR 携带的资产、用户、账号、协议、来源地址和起止时间；播放区右侧的按钮可收起或展开播放列表。对于包含多段的 RDP/VNC 协议录像 TAR，可以在右侧选择分段；播放器跳转到该段开头，仍可在整条时间轴上连续播放和拖动。播放时不访问站点。

| 输入 | 播放 | 导出 MP4 |
| --- | --- | --- |
| 本地 MP4，或含 MP4 的官方离线 TAR | 使用 Qt 原生媒体后端；失败时可尝试系统播放器 | 已是 MP4，无需转码 |
| `.replay.gz`，或含它的官方离线 TAR | Qt 直接渲染 RDP/VNC 协议录像画面 | 可导出 |
| 含 `.replay.json` 和完整 `.part.gz` 的官方离线 TAR | 按分片编号连续播放 | 可导出为一个 MP4 |
| 有初始画面的 `.0.part.gz` | 仅播放首片；其余分片请用完整 TAR | 请使用完整 TAR |
| `.cast` / `.cast.gz` 或含终端录像的官方离线 TAR | 支持 asciinema v2/v3 与常用 ANSI/VT 屏幕指令 | 不转码 |

分片 TAR 以服务端清单核对成员。读取时限制归档、解压数据和帧索引大小；图层和部分定位快照也有上限。RDP/VNC 协议录像的直接播放和导出共用画面渲染逻辑。未支持的协议录像绘制指令会明确报错；音频不在本次迁移范围。

「录像转码」需要先去「设置 → 插件管理」，在录像转码插件（FFmpeg）一行点击「下载」。没有自动下载、后台更新或系统 `PATH` 查找。插件安装在应用数据目录的 `replay-plugins` 下，与 `config.json` 同目录；目录名由应用显示名生成，`OSMClient` 使用 `osm-client`。旧插件目录不会自动迁移，升级后如显示未安装，请在插件管理中重新下载或导入。下载中断或取消后会保留分段缓存，再次点击下载时通过 HTTP Range 从已有数据继续；服务端不支持续传时会自动从头重新下载，最终文件仍会按完整 SHA256 校验。添加 RDP/VNC 协议录像后，每张任务卡片显示会话摘要、详情、进度和输出；转码过程中仍可添加录像，新文件读取完成后会加入当前队列。在右上角「转码设置」弹窗中选择并保存输出目录、分辨率和批量命名规则；取消会保留原设置。也可以在单张任务卡片上重命名。完成后可点「播放结果」在离线播放器里打开 MP4。关闭窗口时队列继续处理，也可以在窗口中取消未完成的任务。

断网可导出 H.264 / `yuv420p` / 10 fps MP4。支持原始分辨率、1080p（默认）、720p 和 360p；预设按比例缩小，不放大原画面，像素尺寸按编码要求取偶数。可用会话 ID（缺少时用原文件名）、用户-资产-账号、用户-资产-账号（会话 ID）命名。输出不会覆盖已有文件，重名时会追加编号；取消或失败时清理本次半成品。插件版本由客户端固定。

下载源为 [ffmpeg-static b6.1.1](https://github.com/eugeneware/ffmpeg-static/releases/tag/b6.1.1) 的 `ffmpeg` 和 `ffprobe` 资产。发布标签与二进制自身版本不一定相同。客户端不镜像或分发这些二进制；上游许可和各架构构建说明见发布页。当前提供 macOS Intel、Apple Silicon（macOS 12 起）、Windows x64、Linux x64/arm64 下载；其余架构只提供播放。Windows 和 Linux 仍需在目标系统验证二进制及媒体后端。Linux 内嵌 MP4 需要能解码 H.264 的系统媒体组件。

网络不可用时，可在「设置 → 插件管理」点击「离线导入」，选择对应平台的 `.tar` 插件包。包根目录必须只包含 `ffmpeg`、`ffprobe`（Windows 为 `ffmpeg.exe`、`ffprobe.exe`）及 `SHA256SUMS`。校验文件采用每行 `SHA256  文件名` 格式。当前内置的 `b6.1.1` 资产（二进制运行时版本为 6.0）仍同时核对内置大小和 SHA256；其他不低于 6.0 的版本按包内 `SHA256SUMS` 与实际文件自校验，并要求 `ffmpeg`、`ffprobe` 版本一致、提供 `libx264`。通过运行检查后才替换已安装插件。自校验包没有发布方签名，只适合导入可信来源的文件。

在可联网的机器下载上述固定版本的对应平台资产后，可用 `python3 scripts/create-ffmpeg-package.py --platform linux-x64 --ffmpeg <文件> --ffprobe <文件> --output <新文件.tar>` 制作固定版本包。制作更高版本包时增加 `--self-verified`，脚本会按实际文件生成 `SHA256SUMS`，客户端导入时再执行版本、哈希和运行检查。`--platform` 还支持 `linux-arm64`、`darwin-x64`、`darwin-arm64` 和 `win32-x64`。不要将下载的二进制或插件包提交到代码仓库。

构建使用 Qt Multimedia、MultimediaWidgets、WebP 图像插件和 zlib。应用安装包只部署播放器使用的 Qt 组件；Windows 和 macOS 的 Qt 6 打包应使用不含 FFmpeg 的系统媒体后端构建。安装包验证会拒绝 FFmpeg、ffprobe、FFmpeg 媒体插件或相关的 `libav*` 库。不要提交用户录像、输出 MP4 或下载的插件。
